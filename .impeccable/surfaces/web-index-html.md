Scope: the single-page web app (web/index.html). Visitor mode: Operate.
Audience/job: department coordinators turn a student list and a lecturer list into a fair supervision list, review it, adjust, export. Constraints: non-technical users, office laptops and phones, WCAG AA, keyboard operable; files never stored.

## Direction contract

THESIS: The result is published like an admission/allocation list in a newspaper supplement, the list people scan for their own name. Refuses the admin-dashboard arrangement (stepper, cards, data grid).

OWN-WORLD: Newsprint grey paper, near-black ink, one deep green for masthead rules and the publish action, blue biro for every human or attention mark (weak matches circled, hand moves underlined, search hits, focus). Libre Franklin heavy for masthead and headings, Spectral for names. Hairline and double rules, no cards, no badges; hierarchy by type scale alone.

STORY: The coordinator drops two lists, sets the rules in one line, presses Publish, sees every lecturer as an equal-scale column with an exact load bar, fixes circled names by hand, exports.

FIRST VIEWPORT: Left-aligned masthead "Supervision List" at display scale with a thin dateline and double rule; under it the desk: student drop zone, lecturer drop zone, rules column ending in the green Publish button. Before publishing, a short three-paragraph notice explains how the list is set.

FORM: Admission list newspaper supplement, position 7 of 7 on my ordered list, seed e752f9d6. Raises: biro marks (doujin catalog), exact-length load bars (labanotation), equal-scale columns (botanical folio), focus one lecturer keeping context (transit map), scale-only hierarchy (type specimen).

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
